# 模拟 IC 经历与证据规则

用于模拟 IC／模拟集成电路设计实习的经历改写与简历制作，不是自动电路设计或 EDA 验证流程。依据目标 JD 和用户材料工作；缺少专业依据时标记待确认，不能仅凭文字认定电路满足指标。用户明确投递其他方向时不套用本规则。

## 采集真实经历

课程设计、科研训练、实验室课题、竞赛和企业实习都可作为材料，先选与目标岗位最相关的内容。根据缺口沿用入口的补问限制，优先确认：

1. 目标岗位或模块，以及已有 JD；没有 JD 时可先做项目初稿，但不推断公司的具体门槛。
2. 项目来源、任务和个人负责部分：自主设计、课程复现、导师方案或团队协作要区分，说明本人做了哪些结构选择、尺寸调整、补偿、分析或验证。
3. 实际完成阶段、关键结果及其条件，证据可以是用户明确确认、获准提供的报告、仿真曲线、测试记录等，不强求公开仓库。

## 写清设计与验证，不堆工具名

项目按“目标与约束 → 个人动作 → 结构/参数取舍 → 验证条件与结果”组织。Cadence、Virtuoso、Spectre、HSPICE 等只在用户确实使用时列出；使用工具不等于掌握完整设计流程。

按模块选择少量有证据的指标，不把下表当作每个项目都必须满足的清单：

| 模块 | 可选重点 | 需要关注的条件或口径 |
| --- | --- | --- |
| 运放 / OTA | 增益、单位增益带宽、相位裕度、压摆率、功耗、噪声或失调 | 供电、负载、输入共模、反馈/环路配置；区分小信号与大信号结果 |
| 比较器 | 延迟、失调、功耗、回踢噪声 | 输入差分电压与共模、负载；动态结构的时钟条件 |
| LDO | 压差、静态电流、线性/负载调整率、瞬态、PSRR、稳定性 | 输入/输出电压、负载范围、输出电容及 ESR；PSRR 所在频率和瞬态阶跃条件 |
| 基准源 | 输出电压、温度系数、线性调整率、启动、功耗 | 温度/供电范围、温漂计算口径及实际启动验证条件 |

ADC/DAC、PLL 或其他模块按 JD 和真实材料选择相应指标，不强行套运放指标。数字有单位，结论保留与其相关的工艺信息（仅限可披露部分）、供电、温度、负载、频率等条件。比较“优化前后”时核对条件和统计口径是否一致；缺失时不推算提升比例，不为了填表强行补指标。

## 阶段与责任边界

- 区分原理分析、原理图前仿、版图、寄生提取后仿、流片和芯片实测；只写实际完成部分。仿真不是实测，前仿不等于后仿，流片不等于指标达标。
- 分开标注典型条件、PVT 工艺角和 Monte Carlo 统计结果。检查了部分角点不等于所有条件通过；做过 Monte Carlo 不自动证明良率。是否需要这些验证由模块、任务和 JD 决定，不把缺少验证升级为虚假经历，也不将其一概视为不合格。
- DRC/LVS 通过只说明对应规则/一致性检查通过，不自动证明性能或可量产性。只有实际完成才写版图、匹配设计或后仿经验。
- 区分课程复现与原创、本人模块与整芯片、导师/团队方案与个人决策。未流片的真实课程项目也可以呈现设计能力，无需包装成量产项目。
- 不要求上传或公开 PDK、模型库、未授权电路/版图、企业数据或未公开课题。采用获准披露的摘要和必要指标即可；公开链接是可选项。
- 主张—证据账本继续沿用原状态规则；待确认内容只留在带标记的草稿，正式 HTML/PDF 前确认或删除。技能里的示例不能当作用户事实。

## 简历与追问示例

以下为条件式示例，仅当用户确实完成这些工作时使用，不复制为默认经历：

原始说法：熟悉 Cadence，完成运放设计。

可用表达：在课程项目中负责两级 CMOS 运放的尺寸调整与补偿参数优化，分析增益、带宽、相位裕度与功耗的取舍，完成指定供电与负载条件下的 AC 和瞬态前仿。

用户有已确认结果时，再补相应条件、数值、单位和验证范围；没有结果时保留可核验的设计动作，不添加“高性能”“全角稳定”或商业收益。

围绕已写入的主张准备追问即可，不默认启动模拟面试：为什么选择该结构？本人调整了什么？稳定性如何测量？指标在哪些条件下成立？如果负载或工艺角变化，预计有什么影响、实际验证过哪些？涉及芯片实测与仿真差异时，仅在用户确实做过实测的前提下追问其经历。

## 成稿检查

- 默认使用真实姓名、学校、时间和职责；允许内部草稿占位，不从模板借用身份或公司。
- 根据相关性安排教育、科研/项目、实习、技能；保持可读字号，通常优先单页，不强制填满不存在的经历。
- 专业技能写实际做过的分析与操作，不因列出模块或工具就写“精通”。GitHub、开源贡献和流片都不是所有实习岗位的统一前提。
- 保留关键指标与条件、阶段标签和个人边界；压缩排版时不删掉这些限定，相关追问不能超出用户证据。
